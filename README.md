# Research Core

**A local-first, AI-powered workspace for serious research — built for macOS.**

Research Core brings your references, literature reviews, AI assistant, and action
items together in one native app — with every byte of your data staying on your own
machine. Connect it to the tools you already use (Zotero, arXiv, Semantic Scholar,
your local filesystem) through the Model Context Protocol, and let a CLI review agent
help you triage papers without surrendering your notes to the cloud.

> Your research. Your disk. Your rules.

---

## ✨ Why Research Core

- **🔒 Local-first by design.** Projects, references, reviews, and chats live in a
  SQLite database on your Mac. Nothing leaves your machine except the calls you
  explicitly make to the LLM provider or MCP servers you configure.
- **🤖 AI-assisted literature review.** Plug in an OpenAI-compatible, OpenAI,
  Anthropic, or local (Ollama) model and a review agent (such as Claude CLI), and
  get structured, citation-aware reviews of your reference set.
- **🧩 MCP-native.** Built-in support for Model Context Protocol servers — Zotero
  Connector, arXiv Search, Semantic Scholar, and a Filesystem bridge — so external
  knowledge sources plug straight into your agents and search.
- **🗂️ Everything in one project.** Each research project holds its references,
  review status, assistant conversations, and a prioritized action list — no more
  juggling four apps to move one chapter forward.
- **🕶️ Optional vault lock.** Lock the app behind a passphrase with an idle-timeout
  policy, so a coffee break never exposes your work-in-progress.

## 🚀 Features

| Surface | What it does |
| --- | --- |
| **Inicio (Dashboard)** | Live status of the current project — review progress, reference counts, recent activity, connected MCP servers. |
| **Refs** | Manage references and attachments; search locally and externally via MCP. |
| **AI Review** | Run citation-aware literature reviews through your configured LLM + CLI agent. |
| **Asistente** | A project-scoped chat assistant backed by your LLM, with access to MCP tools. |
| **Acciones** | A prioritized action list (auto-generated by reviews or manual) with due dates and completion tracking. |
| **Status y config** | Per-project configuration: agents, MCP servers, and integration health. |
| **Ajustes** | Global settings — AI provider/model/keys, review agent path, interface language, local-first toggles, and a danger-zone DB reset. |

### Setup wizard
A first-run wizard walks you through: choosing your app data folder, creating your
first research project, selecting a vault lock policy, and configuring your LLM —
followed by a short interactive tutorial.

## 📦 Download & install

Pre-built **macOS (Apple Silicon)** bundles are produced on every release:

- `Research Core.app` — drag into `/Applications`
- `Research Core_<version>_aarch64.dmg` — disk-image installer

> Requires **macOS 11.0 (Big Sur)** or later. Intel support is not shipped in v0.1.

See the [Releases](../../releases) page for the latest build.

## 🛠️ Build from source

Prerequisites: **Rust (1.77+)**, **Node.js 18+**, and the
[Tauri v2 prerequisites](https://v2.tauri.app/start/prerequisites/) for macOS.

```bash
# 1. Install frontend dependencies
npm install

# 2. Run the dev build (hot-reloading frontend)
npm run tauri dev

# 3. Produce a release bundle (.app + .dmg)
npm run tauri build
```

Artifacts land in `src-tauri/target/release/bundle/`.

## 🏗️ Architecture

```
research-core/
├── src/                     # Frontend (TypeScript + Vite, no framework)
│   ├── main.ts              # Shell, routing, navigation, state
│   ├── api.ts               # Typed Tauri invoke wrappers
│   ├── styles.css           # Design system + all view CSS
│   └── views/               # One module per screen
└── src-tauri/src/           # Rust backend
    ├── lib.rs               # Tauri setup, menu, command registration
    ├── commands.rs          # All #[tauri::command] handlers
    ├── db.rs                # SQLite schema, migrations, seed, queries
    ├── mcp.rs               # MCP registry + client (stdio/http transports)
    └── agent.rs             # CLI review-agent loop
```

**Stack:** Tauri v2 · Rust · SQLite (rusqlite) · TypeScript · Vite · MCP

### Data location
All data is stored locally under:
```
~/Library/Application Support/com.researchcore.app/
├── research-core.sqlite     # the database
└── logs/app.log             # app log
```

## 🔧 Configuration

Open **Ajustes** (top-right) to configure:

- **AI provider** — OpenAI-compatible / OpenAI / Anthropic / Local (Ollama), with
  model, base URL, and API key. Keys are stored only in local SQLite and sent solely
  to the provider you configure.
- **Review agent** — path to the CLI agent binary (e.g. `~/.local/bin/claude`).
- **Interface language** — Español, English, Português, Français.
- **Local-first toggles** — local storage, Zotero sync, offline PDF cache.
- **Danger zone** — wipe and recreate the database from scratch (returns the app to
  the setup wizard).

## 🔌 MCP servers

Research Core ships ready to talk to these Model Context Protocol servers:

| Server | Purpose |
| --- | --- |
| **Zotero Connector** | Pull references from your local Zotero library |
| **arXiv Search** | Search arXiv for new papers |
| **Semantic Scholar** | Enrich references with citation data |
| **Filesystem** | Let agents read project files on disk |

Manage connection status and add your own from the **Status y config** tab.
